# Reverspin

Canvas 2D와 TypeScript로 구현한 공전·방향 반전 회피 게임입니다.

## 실행

Node.js 24 이상과 pnpm이 필요합니다. 테스트는 Node.js의 TypeScript 실행 지원을 사용하며 별도 런타임/테스트 의존성은 없습니다.

```sh
pnpm install
pnpm dev
pnpm test
pnpm build
```

페이지를 열면 바로 시작합니다. **Space**를 누를 때마다 방향이 반전됩니다. 조작 안내는 처음 4초 또는 첫 반전까지 표시됩니다. 게임 오버와 버튼 재시작은 즉시 가능하지만, Space 재시작은 사망 후 800ms 동안 잠깁니다. 이때의 입력은 버리며 안내가 표시된 후 새 Space 입력부터 재시작됩니다. 안내 공간은 유지해 레이아웃이 움직이지 않습니다. 탭·창이 비활성화되면 생존 시간, 생성 타이머와 이동이 멈춥니다.

## Stage 진행과 난이도

생존 시간 1초당 10점이며 `stage = Math.floor(score / 100) + 1`입니다. Stage 1은 0~99점, Stage 2는 100~199점입니다. 명시적인 최대 Stage는 없습니다.

`stageDifficulty(stage)`는 양의 정수 Stage만 받는 순수 함수입니다. 시뮬레이션은 Stage 진입 시에만 새 파라미터를 계산하며 같은 Stage에서는 캐시된 객체를 유지합니다. 시간 기반 연속 난이도와 gameplay 상한/하한은 없습니다. 비행 중인 운석의 속도·경로는 바뀌지 않고, 새 Stage의 운석 속도와 확률은 새로 생성되는 운석에 적용됩니다. 각속도·초당 생성량은 Stage 전환 즉시 바뀌지만 실제 공전 반지름은 이동 각거리를 따라 부드럽게 새 목표로 수렴합니다.

Stage를 `s`, 진행도를 `p = s - 1`로 두면:

`D(s) = 0.002p + 1.65 × [tanh((p - 10) / 5) - tanh(-2)]`

계수는 `D0=0`, `a=0.002`, `b=1.65`, `m=10`, `w=5`입니다. Stage 1 기준을 보존하고 Stage 11(생존 약 100초)에서 증가율이 최대가 됩니다. 폭 5는 약 50초에 대응합니다. 도함수는 `0.002 + 0.33 × sech²((p - 10) / 5)`입니다. 후반 증가율은 0.002에 접근하며 수학적 상한은 없습니다. 극단적 Stage에서의 IEEE-754 정밀도 한계는 수학적 무한 진행과 구분해야 합니다.

각 요소의 민감도를 분리했습니다. `v = D / (D + 3)`으로 두면:

- 목표 공전 반지름: `180 / (1 + D)^0.45`
- 각속도: `3.4 + 1.1D` rad/s
- 운석 기본 속도: `150 + 28D` 논리 단위/초
- 운석 생성량: `0.55 + 0.65D` 개/초
- Normal / Heavy / Swift 확률: `0.8 - 0.25v` / `0.15 + 0.1v` / `0.05 + 0.15v`
- 운석 목표 원판 반경: `360 / (1 + 0.6D)`

Stage 1 기준은 유지합니다. 중반 계수 1.65는 Stage 20의 기존 스케일에 맞췄습니다. Stage 20의 기존/새 반지름은 93.12/94.46, 각속도는 6.70/6.91, 운석 속도는 245.86/239.34, 생성량은 2.65/2.62입니다. 중앙 집중도까지 증가하므로 속도 계수를 32→28, 생성량을 0.7→0.65로 낮췄습니다. Normal 비율도 완만하게 줄어 복합 난이도 상승을 완충합니다. 반지름과 목표점 분산은 양수로 0에 접근하고 속도·생성량은 계속 증가합니다. 확률 합은 1이며 기존의 55/25/20% 극한을 유지합니다. gameplay 최대/최소 clamp는 없습니다.

별도의 다중 생성 확률은 추가하지 않았습니다. 누적 생성량(`spawnProgress`)을 사용하므로 Stage 변경 시 남은 생성 진행도를 보존하며, 높은 생성량에서도 필요한 수만큼 생성합니다.

## 반지름 전환과 부분 궤적

Stage 진입 순간의 **실제 플레이어 반지름**을 출발값으로 저장하고 새 Stage 반지름을 목표값으로 설정합니다. 이후 `abs(angularVelocity × deltaTime)`를 누적합니다. 전환에 필요한 각거리는 **π rad(반 바퀴)**입니다.

`t = clamp(traveledAngle / π, 0, 1)`과 `eased = t² × (3 - 2t)`를 사용해 `radius = oldRadius + (newRadius - oldRadius) × eased`로 계산합니다. 시작과 끝의 반지름 변화율이 0이므로 기존 원에서 출발하고 새 원에 접속하는 부분이 부드럽습니다. clamp는 전환 완료를 위한 진행도에만 적용하며 Stage 반지름의 하한을 만들지 않습니다. 완료 시 목표 반지름을 정확히 사용합니다.

Space 반전은 signed angle의 방향만 바꾸고 누적 이동 각거리는 계속 증가합니다. 따라서 전환 중 반전해도 반지름은 새 Stage 쪽으로 계속 감소합니다. 충돌·Heart 획득·플레이어 렌더링은 모두 이 실제 반지름을 사용합니다.

360도 원형 guide를 제거하고 다음만 표시합니다.

- 앞쪽: `0.55π rad`(약 99°). 현재 방향과 현재 Stage 목표를 유지한다고 가정한 예상 경로를 48개 구간으로 샘플링합니다. 아직 발생하지 않은 다음 Stage나 키 입력은 예측하지 않습니다.
- 뒤쪽: 최근 실제 이동 경로 중 `0.35π rad`(약 63°). 매 0.025 rad 이동마다 좌표와 누적 각거리를 저장하는 96칸 고정 ring buffer를 사용합니다. 최대 약 2.4 rad를 보관하며 화면에는 63° 구간만 표시합니다. 매 프레임 객체를 새로 만들지 않습니다.
- fade: `1 - smoothstep(distance / visibleAngle)`. 가까울수록 선명하고 끝에서는 투명해집니다. 최대 alpha 0.45, 얇은 청회색 선으로 플레이어와 운석보다 낮은 시각적 우선순위를 유지합니다.

`src/trajectory.ts`의 `radiusAtDistance`를 실제 이동, 미래 preview, 과거 기록 샘플링이 함께 사용합니다. Stage 전환 중 앞쪽은 새 원으로 말려 들어가고 뒤쪽은 실제로 지나온 나선 좌표를 보여줍니다. 반전 시 미래 preview만 새 방향을 즉시 따르며, 과거 기록은 뒤집거나 지우지 않고 이후 이동 각거리에 따라 사라집니다. 일시 정지와 게임 오버에서는 기록과 전환도 정지합니다.

## 운석

| 종류 | 반지름(지름) | 속도 배율 | Stage 1 기준 속도 | 표현 |
| --- | --- | ---: | ---: | --- |
| Normal | 17 (34) | 1.0 | 150 | Normal PNG |
| Heavy | 30 (60) | 0.45 | 67.5 | Heavy PNG |
| Swift | 9 (18) | 2.1 | 315 | Swift PNG |

각 운석 속도에 ±10% 편차를 적용해도 종류 간 속도 범위가 겹치지 않습니다. 생성 순간 `Stage 기본 속도 × 종류 배율 × 랜덤 편차`로 최종 `vx/vy`를 저장합니다. 이동 중에는 저장된 velocity만 사용하므로 다음 Stage가 되어도 가속하지 않습니다.

진입 위치의 각도는 전 방향에서 균일하게 선택합니다. 목표점은 반경 `R = 360 / (1 + 0.6D)`인 2차원 원판의 면적 균등 분포입니다. `θ = 2πU`, `r = R√V`, `(x,y) = (r cosθ, r sinθ)`로 샘플링합니다. 평균 목표 거리는 `2R/3`, 반경 절반 안의 비율은 25%로 중심 편향을 피합니다. Stage 1은 기존 선의 최대 편차252보다 넓은360으로 시작하며, Stage 11/20에서는183.08/123.52로 조여집니다. 모든 유한 Stage의 분산은 수학적으로 양수입니다. 생성 뒤에는 고정 velocity로 직선 이동하며 플레이어를 조준하거나 추적하지 않습니다.

운석당 gameplay RNG 순서는 타입→속도 편차→진입 각도→목표 각도→목표 면적의 5회입니다. 기존 4회에서 2차원 표본에 필요한 1회만 추가했습니다. 따라서 이전 버전과 같은 seed의 경로는 달라지지만 새 버전의 동일 seed·입력은 재현됩니다. cosmetic 회전은 RNG를 소비하지 않습니다. Heart 자체의 경로 방식과 3회 RNG 소비는 유지합니다.

고정 seed 4,000개 표본의 기하학적 궤도 교차율은 Stage 1/11/20에서 약61.4/75.9/86.9%입니다. 기존 Stage 1 선 분포 비교는 약78.0%입니다. 실제 피격률은 collider 크기·타이밍·화면 비율에 따라 다릅니다. 각 Stage당20,000개 목표 표본으로 평균·분산·대칭성과 면적 균등성도 검증합니다.

## Heart

- Heart PNG, 논리 반지름 12, 고정 속도 **45 논리 단위/초**입니다. Stage 1의 가장 느린 Heavy(60.75)보다도 느립니다.
- 체력이 3 미만이고 기존 Heart가 없을 때만 생성 타이머가 진행됩니다. 최초 회복 기회는 누적 8초 후에 생성되며, 이후는 **10~16초 균일 무작위(평균 13초)**의 생성 가능 시간입니다. 가득 찬 체력이나 화면을 이동 중인 Heart가 있으면 타이머가 멈추므로 실제 출현 간격은 더 길어집니다. 동시에 존재하는 Heart는 하나입니다.
- 목표점 분산은 `±0.45 × 생성 시 Stage 목표 공전 반지름`으로 운석보다 작습니다. 생성 시 궤도와 높은 확률로 교차하지만 이후 Stage의 반지름 변화·운석 배치 때문에 획득을 보장하지 않습니다.
- 경로와 속도는 생성 후 고정됩니다. 획득하면 즉시 제거하며 체력을 1 회복하고 최대 3을 넘지 않습니다. 피해 무적 중에도 획득할 수 있습니다. 같은 시뮬레이션 단계에서 치명적인 운석 피해를 먼저 받으면 게임 오버가 우선됩니다.
- 놓친 Heart는 화면 밖으로 나가면 제거하며 별도 페널티는 없습니다. 출현 타이머와 속도는 Stage 난이도에 포함되지 않습니다.

## Canvas와 충돌

Canvas는 `100% × 100dvh`로 사용 가능한 창 전체를 채웁니다. 논리 좌표는 화면의 짧은 축을 800으로 두고 긴 축을 화면 비율에 따라 확장합니다. 중앙 원점·동일한 x/y 스케일로 공전 원이 찌그러지지 않습니다. DPR은 backing 해상도에만 적용되며 논리 거리, 속도, 충돌, Stage 계산에는 사용하지 않습니다.

운석·Heart는 생성 방향의 광선과 확장된 논리 viewport 사각형이 교차하는 곳에서 생성합니다. 반지름+16만큼 경계를 확장해 전체 도형이 화면 밖에서 시작합니다. 화면 밖 반지름+64 여유 영역을 지나 **밖으로 이동하는** 오브젝트만 제거합니다. 창을 줄여도 안쪽으로 들어오는 오브젝트를 잘못 지우지 않습니다. 화면 비율에 따라 화면 가장자리에서 중앙까지의 비행 거리는 달라지지만 이동 속도와 생성률은 변하지 않습니다.

HUD에는 좌측 점수, 중앙 Stage, 우측 체력만 표시합니다. Stage 팝업이나 전환 정지는 없습니다. 플레이어 반지름 12, 초기/최대 체력 3, 피격 후 무적 0.5초는 유지합니다.

프레임 간격은 최대 0.05초로 제한하고 최대 1/120초 단계로 시뮬레이션합니다. 원형 충돌에 상대 이동 구간의 최소 거리를 사용해 높은 Stage의 빠른 운석이 샘플 사이를 통과해도 충돌을 놓치지 않도록 했습니다.

## 스프라이트 렌더링

`src/sprites.ts`에서 `public/assets/`의 다섯 PNG 경로·참조·표시 크기를 관리합니다. 모든 이미지의 로드 성공 또는 실패가 결정된 뒤 게임 루프를 시작하며, 실패한 이미지만 기존 도형으로 대체합니다. 이미지 객체는 루프 안에서 생성하지 않습니다.

원본 종횡비를 유지하고 긴 축을 기준으로 표시합니다. 로켓은 논리 지름의 1.75배(42), 운석은 1.15배(Heavy 69 / Normal 39.1 / Swift 20.7), Heart는 1.2배(28.8)입니다. 이는 시각적 크기만 결정하며 원형 collider는 그대로입니다. 로켓은 실제 플레이어 좌표에서 접선 방향으로 회전하고, 무적 시 기존 링과 alpha 깜빡임을 유지합니다. Canvas smoothing을 활성화합니다.

운석은 저장된 `vx/vy`에서 결정한 시각적 위상과 경과 시간으로 0.18~0.35 rad/s의 느린 회전을 계산합니다. 게임 상태에 회전 필드를 추가하거나 게임플레이 RNG를 소비하지 않습니다. 게임 오버·일시 정지에서는 경과 시간도 멈추므로 회전도 정지합니다. Stage 난이도·궤적·충돌·Heart 규칙은 변경하지 않습니다.

## 코드와 검증

- `src/game.ts`: Stage 난이도, 상태, 생성·이동·제거·충돌·회복, 주입 가능한 RNG
- `src/trajectory.ts`: 실제 공전·각거리 기반 반지름 전환·미래 반지름·fade·고정 과거 궤적 버퍼
- `src/viewport.ts`: 화면 비율에서 논리 viewport를 계산하는 순수 함수
- `src/sprites.ts`: 중앙화한 이미지 로딩과 시각적 크기 설정
- `src/render.ts`: 스프라이트와 도형 fallback, 부분 궤적, 균일 스케일과 DPR 대응
- `src/main.ts`: HUD·재시작·포커스·ResizeObserver·단일 requestAnimationFrame 루프
